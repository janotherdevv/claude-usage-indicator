# Design Council PRD — Claude Usage Indicator
> Generated by Design Council v1.0 | Date: 2026-03-13
> Panel: Don Norman · Jony Ive · Steve Jobs

---

## 1. Executive Summary

Claude Usage Indicator is a Linux system tray tool for developers who need ambient awareness of their Claude API quota. The current implementation is functionally complete but visually accidental — it uses GTK defaults throughout, with no considered visual language, no brand identity, and several usability gaps that will confuse users who haven't read documentation.

The council's consolidated vision: transform this into a tool that communicates its state at a glance, feels like a deliberate product rather than a script, and respects the intelligence of its technical audience. The key redesign moves are: replacing the solid-circle icon with a meaningful arc form, applying a considered dark-panel aesthetic to the popup window, and improving the language and information hierarchy throughout.

This is not a full redesign. The architecture — tray indicator + popup window — is correct. The data model is correct. What needs work is the visual execution and the quality of the language.

---

## 2. Project Analysis

**Type:** Linux system tray application (GTK3 + AppIndicator3, Python)
**Target audience:** Developers actively using Claude via OAuth (Claude.ai subscribers)
**Core problem solved:** Users hit unexpected quota limits mid-work session. This tool provides ambient awareness so they can self-regulate usage.
**Usage pattern:** Peripheral/glanceable — users are not staring at this app. They notice the icon color change, occasionally click to see details.
**Platform:** Ubuntu Linux desktop (GNOME or KDE panel). The visual context is a taskbar with many other icons — this app competes for attention in a small 22×22 slot.

**Existing UI inventory:**
- Tray icon: 3 static 22×22 PNG files (solid green/yellow/red circles)
- Tray tooltip: text string `Claude  5h:42%  7d:83%`
- Popup window: GTK3 window with default styling, two progress bar sections
- Right-click menu: Show Usage, Refresh Now, — separator —, Quit

**Key usability issues identified:**
1. Solid circle has no affordance as a usage indicator — it's a traffic light without context
2. "Session (5h)" and "(7d)" labels require prior knowledge to decode
3. Reset time formatted as absolute date (`Fri 13 Mar, 14:30`) rather than relative (`Resets in 2h 15m`)
4. Popup uses no CSS — default GTK styling is visually anonymous and inconsistent with any brand identity
5. No visual link between the tray icon and the popup — they feel like different apps

## 3. Design Principles

The following principles were agreed upon by the council for this specific project:

1. **The icon IS the product.** The tray icon is the primary interface. Users spend 95% of their time not looking at the popup. Every design decision must prioritize what the icon communicates at a glance.

2. **Data should be immediately readable, not decoded.** Replace abbreviations, jargon, and absolute timestamps with plain language and relative time. Users should never need to know what "5h" means — they should read "Last 5 Hours."

3. **Visual language must be consistent end-to-end.** The popup is a zoom into the icon. Same accent color, same arc motif, same weight. A user looking from icon to popup should feel continuity, not context switch.

4. **Respect the developer audience.** This is not a consumer app. Power-user features (Refresh Now, both metrics visible) are valid and should be preserved. Simplification means removing ambiguity, not removing capability.

5. **Aesthetics are a form of trust.** A tool that looks considered feels accurate. Default GTK styling on a data-monitoring app subtly undermines confidence in the data. Visual quality signals engineering quality.

6. **Accessibility is not optional.** All text must meet WCAG AA contrast ratios. Color alone is never the only signal — the arc form conveys quantity independent of color.

7. **Relative context over absolute data.** "Resets in 2h 15m" is more actionable than "Resets at 14:30." "87% used" paired with a near-full arc is more scannable than a number alone.

## 4. Information Architecture

### 4.1 Navigation structure

The application has two interaction surfaces:

```
[Tray Icon]
  │
  ├── Left-click (or right-click in AppIndicator): opens menu
  │     ├── Show Usage      → opens popup window
  │     ├── Refresh Now     → triggers immediate API poll (keep; developer audience expects it)
  │     ├── ─────────────   (separator)
  │     └── Quit
  │
  └── Tooltip (hover): "5h: 42% · 7d: 83%"  (both metrics always visible)

[Popup Window]
  ├── Section: Last 5 Hours
  │     ├── Arc progress + large percentage
  │     └── "Resets in Xh Ym"
  ├── Divider
  └── Section: Last 7 Days
        ├── Arc progress + large percentage
        └── "Resets in Xd Yh"
```

### 4.2 Content hierarchy

**Tray icon (primary):** Arc fill + color state → instant quantitative read
**Tooltip (secondary):** Exact percentages for both metrics → no need to open popup for quick check
**Popup (tertiary):** Full detail — percentage, visual arc, relative reset time — for both metrics

The hierarchy is correct in the current implementation. No structural changes needed — only execution quality.

### 4.3 Screen flow

```
Normal state:
  App starts → fetches usage → sets icon arc + color → sets tooltip → waits 5 min

User wants detail:
  Right-click tray → "Show Usage" → popup appears with latest cached data
  (popup auto-refreshes on open if data is older than POLL_INTERVAL)

User wants fresh data:
  Right-click tray → "Refresh Now" → immediate poll → icon/tooltip updates → popup updates if open
```

## 5. Visual Design

### 5.1 Recommended visual style

**Style:** Dark panel / monitoring aesthetic. Inspired by system monitors, terminal tools, and Claude's own dark-mode UI. Not a consumer app — not rounded corners and pastel gradients. Precision, clarity, ambient confidence.

**Reference mood:** A dark OLED-style card. Dense but not cluttered. Like a good terminal prompt — it gives you exactly what you need and nothing more, but the typesetting is deliberate.

**Key visual decisions:**
- Dark background (`#1a1a1a` or `#1e1e2e` — near-black with slight warmth)
- Single accent color for all active/fill states (Claude brand color — warm coral/orange `#cc785c` or `#d97757`)
- Muted gray for secondary text (reset times, section labels)
- No gradients, no drop shadows on content (subtle shadow only on the window itself)
- Arc motif: thin stroke (2–3px equivalent), rounded linecap

### 5.2 Color palette

| Token | Hex | Usage |
|---|---|---|
| `--bg-primary` | `#1a1a1a` | Popup window background |
| `--bg-card` | `#242424` | Section card backgrounds |
| `--accent-claude` | `#d97757` | Arc fill, percentage text highlight, progress fill |
| `--accent-warn` | `#f5a623` | Arc/progress at 70–89% |
| `--accent-crit` | `#e05252` | Arc/progress at ≥90% |
| `--text-primary` | `#e8e8e8` | Main labels, percentages |
| `--text-secondary` | `#888888` | Reset times, metadata |
| `--divider` | `#333333` | Section separator |

**Tray icon colors (unchanged thresholds, new forms):**
- `< 70%` → `--accent-claude` (warm coral)
- `70–89%` → `--accent-warn` (amber)
- `≥ 90%` → `--accent-crit` (red)

### 5.3 Typography

GTK CSS supports Pango font strings. Use system fonts — no external font loading needed.

| Element | Style |
|---|---|
| Section title ("Last 5 Hours") | `font-size: 11px; font-weight: 600; color: --text-secondary; letter-spacing: 0.5px; text-transform: uppercase` |
| Percentage ("87%") | `font-size: 28px; font-weight: 700; color: --accent-claude` (color tracks utilization state) |
| Reset time ("Resets in 2h 15m") | `font-size: 11px; color: --text-secondary` |
| Window not needed title bar text | Remove/minimize — the content speaks |

### 5.4 Spacing and grid

```
Window padding:     20px all sides
Section padding:    12px inner
Between sections:   1px divider + 16px vertical gap
Progress bar height: 6px (thin, not the default 20px chunky GTK bar)
Progress bar width: full width minus section padding (≈ 280px at minimum window width of 320px)
Percentage + label: left-aligned, percentage on right or large center
Vertical rhythm:    section title → 8px → percentage + bar → 6px → reset time
```

## 6. Key Components

### 6.1 Main components identified

**TrayIcon (enhanced)**
- Replace 3 static PNG circles with 3 static arc-form PNGs (or dynamic cairo rendering)
- Arc form: thin ring (~3px stroke), partially filled to indicate approximate state
- Three states: ~25% full (ok), ~75% full (warn), ~95% full (crit)
- Background of arc stroke: `rgba(255,255,255,0.15)` unfilled track
- Filled portion: respective accent color

**PopupWindow (redesigned)**
- Apply dark CSS via `Gtk.CssProvider` loaded at app startup
- Remove title bar text or replace with minimal app name
- Two `UsageSection` cards, each containing: section title, large percentage, thin progress bar, relative reset time
- Thin horizontal separator between sections

**UsageSection (new component extracted from `_section`)**
- Self-contained GTK Box with CSS class `usage-section`
- Props: label (str), utilization (float 0–100), resets_at (str ISO)
- Internally renders: title label, percentage label, progress bar, reset label
- Progress bar color driven by CSS class added based on utilization threshold

**RelativeTimeFormatter (replace `format_reset_time`)**
- Input: ISO datetime string
- Output: "Resets in 2h 15m" / "Resets in 3d 4h" / "Resetting now" / "Reset X min ago"
- Falls back to absolute time if parsing fails

### 6.2 Design system recommendations

Since this is a single-file Python app, the "design system" is a GTK CSS string embedded in the source or loaded from a `style.css` file in the same directory.

Recommended approach: `style.css` file in the project root, loaded once at startup via:
```python
css_provider = Gtk.CssProvider()
css_provider.load_from_path(str(SCRIPT_DIR / "style.css"))
Gtk.StyleContext.add_provider_for_screen(
    Gdk.Screen.get_default(),
    css_provider,
    Gtk.STYLE_PROVIDER_PRIORITY_APPLICATION
)
```

This keeps the Python clean and the CSS editable independently.

### 6.3 Critical states and variants

| State | Icon | Popup behavior |
|---|---|---|
| Loading (first poll) | Gray arc (0% fill) | "Fetching usage data..." |
| Error (network/auth) | Gray arc | Error message in red, timestamp of last successful fetch |
| Token expired | Red arc | "Claude token expired — please re-authenticate" |
| OK (< 70%) | Coral arc, partial fill | Normal display |
| Warning (70–89%) | Amber arc | Percentage label turns amber |
| Critical (≥ 90%) | Red arc | Percentage label turns red; consider subtle pulsing animation |
| Both metrics differ significantly | Max drives icon | Both shown in popup; dominant one visually emphasized |

## 7. User Flows

### 7.1 Main flow (happy path)

1. App starts silently in system tray — coral arc icon, ~20% fill (example)
2. User glances at tray — sees partial arc, it's calm coral, all is fine — returns to work
3. After 3h of heavy Claude use — icon turns amber, arc now ~75% full
4. User hovers — tooltip: "5h: 78% · 7d: 34%" — understands 5h session is the constraint
5. User right-clicks → "Show Usage" — popup appears
6. Popup shows: "Last 5 Hours: **78%** / Resets in 1h 20m" and "Last 7 Days: **34%** / Resets in 4d 2h"
7. User makes informed decision about their remaining session work
8. User closes popup (X or click away) — returns to work

### 7.2 Secondary flows

**Refresh flow:**
1. User suspects data is stale (last poll was 4 min ago, they just sent 50 messages)
2. Right-click → "Refresh Now"
3. Icon briefly shows previous state, then updates within ~2 seconds
4. Tooltip updates immediately — no need to open popup

**Error flow:**
1. Network is unavailable — API call fails
2. Icon turns gray (neutral — not a usage alert, a connectivity state)
3. Tooltip: "Claude: network error"
4. "Show Usage" popup: shows last known data with timestamp ("Last updated: 8 min ago") + error message below

**Token expiry flow:**
1. Token expires overnight
2. Next 5-minute poll fails with auth error
3. Icon turns red (but this is a different red than critical usage — ideally distinct)
4. Tooltip: "Claude: token expired"
5. Popup: clear message directing user to re-authenticate (`claude` CLI or browser)

### 7.3 Edge cases and error states

| Edge case | Current behavior | Recommended behavior |
|---|---|---|
| No credentials file | Error label in popup | Specific guidance: "Run `claude` to authenticate" |
| Token expired | Generic error | "Your Claude session has expired. Re-run `claude`." |
| API returns unexpected schema | Crash / empty data | Graceful fallback with last-known data |
| Both utilization values are 0 | Shows 0% | Show 0% — this is valid (fresh window) |
| `resets_at` missing from API | No reset time shown | Acceptable — omit that line cleanly |
| User opens popup while poll in progress | Shows stale data | Show stale data + spinning indicator or "Updating..." |

## 8. Technical Recommendations

### 8.1 Suggested UI framework/library

Keep GTK3 + AppIndicator3. No framework change needed. The visual improvements are achievable entirely through:
1. `Gtk.CssProvider` for styling
2. Better icon PNGs (redesigned arc form, same 22×22 resolution)
3. `format_reset_time` replacement with relative time calculation
4. Label text copy changes (no structural changes to widget tree required)

For the dynamic icon (advanced option), use `cairo` (available via `from gi.repository import cairo`) to render the arc directly into a `Gdk.Pixbuf`, then call `indicator.set_icon_full()` with a temp file or pixbuf path after each poll.

### 8.2 Responsive strategy

This is a fixed-width desktop popup. Responsive design is not applicable. Recommended fixed dimensions:
- Popup window: `set_default_size(320, -1)` — fixed width, natural height
- Progress bars: `set_size_request(280, 6)` — thin, full-width within padding

### 8.3 Accessibility (WCAG)

| Requirement | Implementation |
|---|---|
| AA contrast for text | `--text-primary (#e8e8e8)` on `--bg-primary (#1a1a1a)` = 14.3:1 ✓ |
| AA contrast for secondary | `--text-secondary (#888888)` on `--bg-primary (#1a1a1a)` = 4.6:1 ✓ |
| Color not the only signal | Arc fill level communicates quantity independent of color |
| Percentage text explicit | Always show numerical % alongside arc/bar |
| Error states text-described | Never rely on color alone for error states |
| Keyboard access | GTK menus are keyboard-accessible by default — preserve this |

### 8.4 Performance considerations

- CSS loading: once at startup, negligible cost
- Icon regeneration: if using static PNGs, no performance concern; if using dynamic cairo rendering, generate only when utilization changes significantly (>1% delta), not on every poll
- Popup rebuild on each show: current behavior is correct — fresh GTK widgets avoid state bugs; GTK widget creation is fast enough not to be perceptible
- `GLib.timeout_add_seconds(300)` polling: correct; no threading needed

## 9. Council Disagreements

These are points where no consensus was reached. The user must decide.

**A — Window chrome style**
- **Option A1 (Jony Ive):** Borderless popup window (`set_decorated(False)`) with a custom close button drawn in CSS. Cleaner aesthetic, removes the native GTK title bar.
  - *Risk:* Users may not know how to move/close the window; may conflict with accessibility tools; notoriously fragile across GNOME versions.
- **Option A2 (Norman + Jobs):** Keep native GTK window chrome. Apply CSS only to the content area. Reliable, familiar, system-integrated.
  - *Recommendation:* Start with A2. Implement A1 only if borderless windows are stable on your target Ubuntu version.

**B — Icon implementation complexity**
- **Option B1 (Jony Ive — Dynamic):** Render a cairo arc in Python after each poll, write to a temp PNG, call `set_icon_full()`. The icon reflects exact utilization (e.g., 73% → arc 73% full).
  - *Benefit:* Highly informative — users get quantitative data from the icon alone.
  - *Cost:* ~30 lines of cairo code, temp file management, risk of flicker on icon update.
- **Option B2 (Norman/Jobs — Three Enhanced Static Icons):** Redesign the three PNG icons to use an arc form instead of a solid circle. Keep the three-state threshold logic. No code complexity increase.
  - *Recommendation:* B2 for initial implementation. B1 as a follow-up enhancement if desired.

Prioritized by impact vs. implementation cost:

| Priority | Change | Impact | Effort |
|---|---|---|---|
| 1 | Replace `format_reset_time` with relative time ("Resets in 2h 15m") | High UX improvement | Low — pure Python |
| 2 | Update label text: "Session (5h)" → "Last 5 Hours", "(7d)" → "Last 7 Days" | Clarity | Trivial |
| 3 | Add `style.css` with dark panel aesthetic and apply via `CssProvider` | Visual quality | Medium — CSS + Gdk import |

| 5 | Make percentage the typographic hero (large, bold, accent-colored) | Visual hierarchy | Low — CSS |

| 7 | Improve error state messages (specific guidance for token expiry, no credentials) | Error UX | Low |

## Appendix: Debate Record

**Key positions and turning points:**

**Round 1 — Icon identity**
Norman pushed for a letter/symbol brand marker. Jobs killed it on legibility grounds. Ive proposed the arc form — a ring that fills to represent utilization. Jobs immediately converted. Norman accepted it with the condition that the tooltip preserves explicit both-metric text. The arc concept was the pivotal idea of the entire session.

**Round 2 — Popup window**
Jobs made the strongest individual contribution: replacing absolute reset times with relative time ("Resets in 2h 15m"). Norman agreed immediately and uncharacteristically without caveat. This validated Jobs' "work backward from user intent" principle in a way Norman found genuinely compelling. The popup structure (two sections, percentage + bar + reset time) was validated by all three — only the execution quality was contested.

**Round 3 — Interaction model**
Ive proposed eliminating "Refresh Now." Norman and Jobs surprisingly aligned to preserve it — both acknowledged that the developer audience has a legitimate mental model of manual refresh. This was the council's rarest formation: Norman + Jobs overriding Ive's minimalism.

**Round 4 — CSS theming**
Ive owned this round. Jobs and Norman both deferred to Ive's specific CSS aesthetic direction. The dark panel + single accent color + arc motif achieved genuine three-way buy-in. Norman's only intervention was the WCAG contrast requirement, which Ive accepted without resistance (he'd already designed to sufficient contrast).

**Round 5 — Dynamic vs. static icons**
The dynamic icon (cairo-rendered continuous arc) was the final debate point. All three agreed it was the *ideal* solution. They split only on whether it was worth the implementation complexity in the initial release. PRD reflects this as a recommended enhancement rather than a blocker.
