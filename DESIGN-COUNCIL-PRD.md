# Design Council PRD — Claude Usage Indicator
> Generated by Design Council v1.1 | Date: 2026-03-13
> Panel: Don Norman · Jony Ive · Steve Jobs

---

## 1. Executive Summary

Claude Usage Indicator es una app de system tray para Ubuntu que permite a desarrolladores monitorear su uso de Claude API de un vistazo. Es una herramienta que se consulta decenas de veces al día, en segundos, y se cierra de inmediato. Ese patrón de uso exige el modelo de interacción de menor fricción posible.

Esta versión del PRD consolida dos sesiones del consejo. La primera estableció: auto-fetch al abrir el popup, eliminación del botón Refresh, barras con color semántico, ventana sin decoración, y porcentaje grande como elemento visual dominante. La segunda — este documento — resuelve los dos problemas restantes: el doble clic para llegar al popup, y los iconos del tray.

El consejo acordó migrar de AppIndicator3 a `Gtk.StatusIcon`: clic izquierdo abre el popup directamente sin menú intermedio; clic derecho muestra el menú de acciones secundarias (solo Quit). El icono pasa de un círculo sólido de color a un arco de progreso circular (medidor de 270°) con track base tenue y fill de color semántico — la forma comunica estado sin necesitar texto.

## 2. Project Analysis

**Qué es:** App Python de una sola archivo, GTK3, system tray para Ubuntu. Monitorea dos ventanas de uso de la API de Claude: sesión de 5 horas y semana de 7 días.

**Usuario objetivo:** Desarrolladores usando activamente Claude API/Claude.ai que necesitan monitorear sus límites de uso durante la jornada. Alta frecuencia de consulta, contexto de uso: mientras trabajan en otra cosa.

**Estado actual post-sesión 1:**
- Auto-fetch al abrir popup ✓
- Barras con color semántico ✓
- Porcentaje grande (Jobs' Option A) ✓
- Ventana sin decoración, cierre en focus-out ✓
- "Refresh Now" eliminado ✓
- Todavía requiere doble clic (AppIndicator3) ✗
- Iconos: círculos sólidos sin significado de medición ✗

## 3. Design Principles

1. **Un clic, un resultado.** Clic en el tray = popup con datos. No hay paso intermedio.
2. **La forma comunica estado.** El icono del tray debe ser legible sin color — el arco vacío vs. lleno transmite urgencia antes de que el cerebro procese el color.
3. **El sistema siempre está vivo.** Fetch automático en cada apertura. El usuario nunca gestiona la frescura de los datos.
4. **Estado visible en el icono.** El color del arco y el del popup son el mismo sistema semántico: verde / ámbar / rojo.
5. **Reducir a lo esencial.** Menú de clic derecho tiene un solo ítem: Quit. Todo lo demás sobra.
6. **Feedback a través del movimiento.** Las barras del popup animan de 0 al valor real durante el fetch — el movimiento es la retroalimentación.
7. **Transparencia sin botones.** El timestamp "Updated just now" reemplaza cualquier control manual.

## 4. Information Architecture

### 4.1 Navigation Structure

```
Tray Icon (siempre visible, arco de progreso coloreado)
│
├── Clic izquierdo → Popup inmediato (fetch en background)
│   ├── Section 5h: porcentaje grande + barra coloreada + reset time
│   ├── Section 7d: porcentaje grande + barra coloreada + reset time
│   └── "Updated just now" timestamp
│
└── Clic derecho → Menú mínimo
    └── [Quit]
```

**Eliminado vs. AppIndicator3:**
- Menú en clic izquierdo (ya no existe)
- "Show Usage" como ítem de menú (ya no existe)
- "Refresh Now" como ítem de menú (ya no existe)

### 4.2 Content Hierarchy

1. Estado del icono en tray (arco + color) — lectura periférica, sin clic
2. Porcentajes grandes en popup — primera lectura al abrir
3. Barras de progreso coloreadas — confirmación proporcional
4. Reset times — información secundaria
5. Timestamp "Updated" — confianza en la frescura, no requiere atención activa

### 4.3 Screen Flow

```
Desarrollador trabajando
  → Visión periférica detecta icono ámbar/rojo en tray
    → Clic izquierdo
      → Popup aparece inmediatamente
        → Barras pulsan (fetch en curso, ~300ms)
        → Valores se estabilizan
        → Desarrollador lee: 5h: 84%, 7d: 31%
        → Mueve foco
          → Popup se cierra automáticamente
```

## 5. Visual Design

### 5.1 Recommended Visual Style

Sistema de dos capas: tray (siempre visible, icono de arco) + popup (efímero, datos completos). El icono del tray usa el mismo vocabulario de color que el popup.

### 5.2 Color Palette

| Estado | Color | Hex | Umbral |
|---|---|---|---|
| OK | Verde | `#26A269` | < 70% |
| Warning | Ámbar | `#E5A50A` | 70–89% |
| Critical | Rojo | `#C01C28` | ≥ 90% |
| Track base | Blanco | `rgba(255,255,255,0.25)` | siempre visible |

### 5.3 Typography

Heredada del sistema GTK (Inter / Ubuntu font). Sin fuentes custom.

| Elemento | Tamaño | Peso |
|---|---|---|
| Porcentaje en popup | `xx-large` Pango | Bold |
| Etiqueta de sección | System default | Bold |
| Reset time / timestamp | System default -1pt | Regular, `dim-label` |

### 5.4 Spacing and Grid — Icono

```
Canvas:         22 × 22 px
Margen externo: 2 px (todos los lados)
Diámetro arco:  18 px (exterior)
Grosor trazo:   3 px
Diámetro inner: 12 px (espacio negativo central)
Ángulo:         270° (de 225° a 135°, sentido horario)
                Inicio: 7 en punto (225°)
                Fin:    5 en punto (135°)
Fondo:          Transparente
```

## 6. Key Components

### 6.1 Tray Icon — Arco de Progreso

**Generación programática con Cairo (Python):**

```python
import cairo
import math

def render_arc_icon(utilization, size=22):
    """
    Renderiza un arco de progreso circular en un surface Cairo ARGB32.
    utilization: float 0–100
    Retorna: bytes PNG
    """
    surface = cairo.ImageSurface(cairo.FORMAT_ARGB32, size, size)
    ctx = cairo.Context(surface)

    cx, cy = size / 2, size / 2
    margin = 2
    radius = (size - margin * 2) / 2 - 1.5  # centrado con grosor
    start_angle = math.radians(225)   # 7 en punto
    end_angle   = math.radians(135)   # 5 en punto (270° de recorrido)
    line_width  = 3

    ctx.set_line_width(line_width)
    ctx.set_line_cap(cairo.LINE_CAP_ROUND)

    # Track base (blanco 25%)
    ctx.set_source_rgba(1, 1, 1, 0.25)
    ctx.arc(cx, cy, radius, start_angle, end_angle)
    ctx.stroke()

    # Fill proporcional al uso
    fraction = min(utilization / 100.0, 1.0)
    fill_end = start_angle + fraction * math.radians(270)

    if fraction > 0:
        color = _arc_color(utilization)
        ctx.set_source_rgb(*color)
        ctx.arc(cx, cy, radius, start_angle, fill_end)
        ctx.stroke()

    buf = surface.write_to_png(None)  # bytes
    return buf
```

**Tres archivos PNG pre-generados** para AppIndicator / StatusIcon (no soportan Cairo dinámico):
- `icon_ok.png` — arco verde al ~50% fill (estado representativo)
- `icon_warn.png` — arco ámbar al ~80% fill
- `icon_crit.png` — arco rojo al ~95% fill

> **Nota:** Dado que `Gtk.StatusIcon` carga un archivo estático, los iconos son pre-generados con valores representativos de cada estado, no el porcentaje exacto en tiempo real. El porcentaje exacto vive en el tooltip y en el popup.

### 6.2 Gtk.StatusIcon — Migración desde AppIndicator3

```python
self.status_icon = Gtk.StatusIcon()
self.status_icon.set_from_file(icon_path)
self.status_icon.set_tooltip_text("Claude  5h:0%  7d:0%")
self.status_icon.connect("activate", self._on_left_click)       # clic izquierdo
self.status_icon.connect("popup-menu", self._on_right_click)    # clic derecho

def _on_right_click(self, icon, button, activate_time):
    menu = self._build_menu()  # solo Quit
    menu.popup(None, None, Gtk.StatusIcon.position_menu, icon, button, activate_time)
```

### 6.3 Critical States and Variants

| Estado | Icono | Popup |
|---|---|---|
| OK (< 70%) | Arco verde | Barras verdes |
| Warning (70–89%) | Arco ámbar | Barras ámbar |
| Critical (≥ 90%) | Arco rojo | Barras rojas |
| Loading | Último icono conocido | Barras pulsando |
| Error token | `icon_crit.png` | Mensaje de error |
| Error red | Último icono conocido | Mensaje + last-updated |

## 7. User Flows

### 7.1 Main Flow (Happy Path)

1. Desarrollador hace clic izquierdo en el icono del tray
2. Popup aparece inmediatamente con barras en modo pulse
3. Fetch en background completa (~300ms)
4. Barras se animan al valor real, timestamp aparece
5. Desarrollador lee los datos, mueve el foco
6. Popup se cierra automáticamente

### 7.2 Secondary Flows

**Lectura periférica (flujo más frecuente):**
- El icono cambia de verde a ámbar o rojo
- Desarrollador lo ve sin clicar
- No necesita abrir el popup si el color es suficiente

**Error de red:**
- Popup muestra el último dato conocido con timestamp de cuándo fue
- Mensaje de error sutil bajo los datos

### 7.3 Edge Cases

- **Fetch duplicado:** Guard `_fetching: bool` — segundo clic antes de que termine el primero muestra datos cacheados, sin lanzar otro fetch
- **Ventana cerrada antes de que llegue el fetch:** `_on_fetch_done` verifica `window.get_visible()` antes de actualizar
- **Token expirado:** Popup muestra error, icono usa `icon_crit.png`
- **Utilización > 100%:** Cap a 1.0 en `set_fraction()`, muestra "100%"

## 8. Technical Recommendations

### 8.1 Gtk.StatusIcon vs AppIndicator3

Usar `Gtk.StatusIcon` para obtener comportamiento de clic izquierdo directo:

| | AppIndicator3 | Gtk.StatusIcon |
|---|---|---|
| Clic izquierdo | Siempre abre menú | Dispara `activate` signal |
| Clic derecho | Siempre abre menú | Dispara `popup-menu` signal |
| Estado en GNOME | Soportado activamente | Deprecated en GTK3, funcional |
| HiDPI | Sí | Sí |
| Tooltip | `set_title()` | `set_tooltip_text()` |

> `Gtk.StatusIcon` está deprecated en GTK3 pero sigue funcionando en Ubuntu 22.04/24.04. Para este proyecto (single-file, GTK3, Ubuntu) es la solución correcta.

### 8.2 Generación de iconos con Cairo

Dependencia adicional: `pycairo` (normalmente disponible como `python3-cairo` en Ubuntu).

```bash
sudo apt install python3-cairo
```

Los tres iconos PNG se generan una sola vez al inicio del script si no existen, o se regeneran si el formato cambia. No requieren binarios externos.

### 8.3 Accessibility (WCAG)

- `set_tooltip_text()` en StatusIcon provee texto accesible
- Heading interno en popup ("Claude Usage") preservado para AT-SPI
- Contraste de texto en barras ámbar: usar texto oscuro (`#1a1a1a`), no blanco

### 8.4 Performance

- Iconos generados una vez, guardados en disco como PNG
- El tooltip se actualiza en cada poll (cada 5 min) y en cada fetch on-demand
- Sin impacto adicional vs. implementación anterior

## 9. Council Disagreements

**Opción A (Norman) — Fill mínimo visible:**
El arco fill nunca va a 0 aunque el uso sea 0%. Mínimo visual del 8% para que la forma no "desaparezca" cuando el uso es muy bajo.

**Opción B (Jobs/Ive) — Fill exactamente proporcional:**
Fill = uso real. 0% = solo el track tenue, sin artificio. El track base es suficiente para identificar el icono como un medidor incluso vacío.

*El consejo recomienda Opción B — la honestidad de la representación es más importante que el comfort visual.*

## Appendix: Debate Record

**Sesión 1 (PRD v1.0):**
Eliminación de "Refresh Now", auto-fetch al abrir, barras coloreadas con CSS, porcentaje grande (Jobs' Option A), ventana sin decoración, cierre en focus-out, timestamp de actualización, guard `_fetching`.

**Sesión 2 (PRD v1.1 — este documento):**

**Round 1 — Interacción directa:** Consenso inmediato en `Gtk.StatusIcon`. Jobs lo propuso, Norman objetó por deprecated, Ive lo resolvió: deprecated ≠ no funciona, y este es GTK3/Ubuntu hoy.

**Round 2 — Forma del icono:** Jobs mató el logo-en-icono ("la forma ES la identidad"), Ive lo elaboró (arco de progreso como medidor universal), Norman validó la metáfora cognitiva. Track base propuesto por Norman para preservar forma a uso bajo — aceptado por todos.

**Round 3 — Detalles técnicos:** Convergencia en 270°, 3px, 2px margen, fondo transparente. Jobs casi propone texto en el icono — Ive lo cortó en una palabra: "No."

**Round 4:** El round más breve de la historia del consejo.

**Sin resolver:** Fill mínimo (Norman) vs. fill exacto (Jobs/Ive). Consejo recomienda Opción B.
